## 0. Owner's working rules (must follow)

The project owner (Abu Sayed) builds this as a **live demo for a "Software Engineer — AI &
Automation" job interview at a private hospital in Dhaka**. Every feature must be really built,
cleanly layered, secure, easy for non-technical staff, and explainable in an interview.

1. **Language:** the owner writes in Bangla/Banglish. Reply to the owner in **Bangla** (simple
   words; technical terms may stay in English). Code, comments, commit messages and these guides stay in English.
2. **Work in phases.** The owner sends one prompt per phase (15 phases, see §3). Build **only** that
   phase. Future menu items stay as placeholders.
3. **Before coding a phase:** read both guides, inspect the code, give a short plan (files to add or
   change, conflicts). **If anything conflicts with existing code, ask the owner first.** Never delete
   or rewrite working code without explaining why.
4. **Commit after each major step** with a conventional message (`feat(backend): …`, `fix(frontend): …`,
   `docs: …`). **Do not add AI/assistant co-author lines or any "generated by" text to commits or PRs.**
5. **At the end of every phase**, give the owner (in Bangla): every file created/changed with 1–2 sentences
   on why; commands to run; a step-by-step manual test checklist (which account, what to check);
   likely interview questions with short simple answers. Then update §13 (Phase log) of this file
   and the matching section of the frontend guide.
6. **Repository layout is fixed:** only `backend/` and `frontend/` at the repository root. **Do not**
   create files or folders at the root (no root README, `.gitignore`, `.gitattributes`, `docs/`, Docker files).
7. **No Docker.** The project runs directly with `npm`.
8. **No assistant/agent files in git:** `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.cursor/` etc. must never be
   committed (they are in `.gitignore`). Put any project knowledge into these two README guides instead.
9. **Secrets never in git.** `.env` / `.env.local` are ignored; `.env.example` files hold placeholders only.
10. **Naming:** product = **Testolife**, hospital = **Testolife Hospital** (Keraniganj, Dhaka), patient
    assistant = **"Testo Life Assistant"**. **User-facing text must not say "AI"** (no "AI-powered", "AI Alerts",
    "AI chat"). Internal code names like `modules/ai`, `ai_chat`, `/reception/ai-alerts` may stay.
    The chat must still honestly say it is an automated assistant, not a human.
11. **AI never diagnoses or prescribes.** It gives information, books, reminds and summarises; humans decide.
    Emergencies are handled by code (no AI) and handed to staff immediately.
12. **Medical / financial data is never hard-deleted** (soft delete via `basePlugin`).
13. **Demo data is fictional only.** Never real patient data.
14. The owner develops on **Windows** (PowerShell / Git Bash). Keep commands cross-platform.

npm install
cp .env.example .env        # then fill it in (see table below)
npm run seed                # demo departments/doctors + 9 demo accounts (idempotent)

## 5. Architecture

```
request → pino-http → helmet → CORS(CLIENT_URL) → body limit → cookie-parser → sanitize (NoSQL)
        → verifyOrigin (CSRF) → rate limit → /api/v1 router
        → [authenticate() → requirePermission()] → validateRequest(zod) → controller → service → model
errors anywhere → globalErrorHandler → { error: { code, message, details } }
```

**Rule: business logic lives only in services.** Controllers translate HTTP ↔ service calls.
Services are reused by routes, assistant tools, jobs and tests.

### Folder map (`backend/src`)

| Folder | Responsibility |
| --- | --- |
| `config/` | `env.ts` (Zod-validated env — nothing else reads `process.env`), `database.ts`, **`permissions.ts`** (RBAC source of truth), `index.ts` (legacy named exports) |
| `middlewares/` | `sanitize`, `verifyOrigin`, `rateLimiter` (general, login, refresh, chat), `validateRequest`, `authenticate`, `authorize` (`requirePermission`, `requireAnyPermission`, `assertCanAccess`), `notFound`, `globalErrorHandler` |
| `routes/` | `index.ts` mounts every module under `/api/v1`; `health.route.ts` |
| `controllers/`, `services/` | Shared non-domain endpoints (health) |
| `modules/auth` | login / refresh / logout / me / change-password, tokens + cookies, `RefreshToken` model |
| `modules/users` | `User` model, user management API |
| `modules/audit` | `AuditLog` model (append-only), `recordAudit()`, read API |
| `modules/hospital/*` | appointment, doctor, department, dashboard (prototypes) |
| `modules/ai/chat` | Testo Life Assistant (Gemini, tools, guardrails) |
| `modules/basic_modules/management` | Template CMS for terms/about/privacy pages (edit needs `settings:manage`) |
| `models/` | `counter.model.ts` (atomic sequences), `plugins/basePlugin.ts` |
| `validators/` | Reusable Zod pieces: `password.ts`, `common.ts` (ObjectId, BD phone, pagination) |
| `errors/` | `AppError` + translators (Zod, Mongoose validation, CastError, duplicate key) |
| `sockets/` | Socket.IO: `emitToPermission`, `emitPublic`, `disconnectUser` |
| `jobs/`, `ai/` | Empty — for Phase 13 (cron) and shared AI infrastructure (RAG, Phase 12) |
| `utils/` | `logger`, `catchAsync`, `sendResponse`, `date` (Dhaka time), `escapeRegex` |
| `DB/` | Idempotent seeders (`hospitalSeed.ts`, `demoUsers.ts`) |
| `fileUpload/` | Legacy template, not mounted |

A feature module has: `x.model.ts`, `x.validation.ts`, `x.service.ts`, `x.controller.ts`, `x.route.ts`
(older prototype modules combine route + controller in `x.route.ts`).

### Conventions

- **Success response:** `{ success, statusCode, message, data, pagination? }` via `sendResponse()`.
  Pagination shape: `{ page, limit, total, totalPages }` (`buildPagination()` in `interface/global.interface.ts`).
- **Error response (the only one):** `{ error: { code, message, details } }`.
  Codes: `BAD_REQUEST`, `VALIDATION_ERROR` (details = `[{ path: "body.email", message }]`), `INVALID_ID`,
  `INVALID_JSON`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `DUPLICATE_KEY` (409),
  `PAYLOAD_TOO_LARGE`, `RATE_LIMITED`, `INTERNAL_ERROR`, `INVALID_CREDENTIALS`, `ACCOUNT_LOCKED` (423),
  `ACCOUNT_DISABLED`, `PASSWORD_CHANGE_REQUIRED`, `SESSION_EXPIRED`, `SESSION_REVOKED`, `CSRF_REJECTED`.
  5xx messages are hidden in production. 4xx messages are written for hospital staff (the frontend shows them).
- Throw `new AppError(status, message, code?, details?)` for expected errors; wrap handlers in `catchAsync`.
- Validate with `validateRequest(z.object({ body, query, params }))`; parsed values replace the raw ones.
- **Every domain model uses `basePlugin`**: timestamps, `createdBy/updatedBy`, soft delete
  (`isDeleted/deletedAt/deletedBy`, auto-excluded from queries; `.setOptions({ withDeleted: true })` to include;
  `doc.softDelete(userId)`). Not used on `AuditLog`, `RefreshToken`, `Counter`.
- **Codes/serials:** `nextCode("patient", "TL")` → `TL-000124` (atomic `$inc`, pass a session inside transactions).
- **Time zone:** the hospital runs on `Asia/Dhaka` — use `utils/date.ts`.
- **Logging:** `logger.info/warn/error` (pino). Never log passwords, tokens or patient details.
- **Real-time:** events with personal data → `emitToPermission("perm", event, payload)`; public screens →
  `emitPublic("queue:changed")` (no data). Never `io.emit` personal data.
- **Search:** always `escapeRegex()` user input before `$regex`.

## 6. Authentication (Phase 2)

| Topic | Decision |
| --- | --- |
| Passwords | bcrypt (cost 12). Policy: ≥ 8 chars with letters and numbers (`validators/password.ts`). |
| Access token | JWT HS256, 15 min, claims `sub` (user id), `role`, `sid` (session id). Cookie `tl_access`, path `/`. |
| Refresh token | 384-bit random string, 7 days, cookie `tl_refresh`, **path `/api/v1/auth` only**. Only its SHA-256 hash is stored (`RefreshToken`, TTL index removes expired rows). |
| Session flag | Cookie `tl_session=1` (no secret) so the frontend route guard knows someone is signed in. |
| Cookie flags | `httpOnly`, `sameSite=lax`, `secure` in production. Tokens never appear in response bodies or JavaScript. |
| Same origin | The frontend calls `/api/v1` on its own origin; Next.js rewrites to this API. |
| Every request | `authenticate()` verifies the JWT, checks the session is alive (`RefreshToken` with that `sessionId` not revoked) and the user is active, and reads role/permissions **from the DB** (instant logout / deactivation / role change). |
| Rotation | `/auth/refresh` issues a new refresh token, revokes the old (`revokedReason: "rotated"`, `replacedBy`). |
| Theft detection | A rotated token used again (after the 10 s grace) → revoke **all** sessions of that user, audit `TOKEN_REUSE_DETECTED`, `401 SESSION_REVOKED`. Tokens revoked for other reasons just answer `SESSION_REVOKED`. |
| Lockout | 5 wrong passwords → `lockUntil` = now + 15 min (atomic `$inc`), `423 ACCOUNT_LOCKED` with `details.retryAfterSeconds`. |
| Enumeration | Same message for unknown email and wrong password; unknown emails still run a bcrypt compare against a dummy hash (equal timing). |
| Rate limits | Login 20 / 15 min / IP, refresh 60 / 15 min / IP. |
| Deactivation | Blocks login, revokes all sessions, disconnects sockets. |
| New users / resets | Temporary password (shown once to the admin) + `mustChangePassword` → every route except `/auth/me`, `/auth/change-password`, `/auth/logout(-all)` answers `403 PASSWORD_CHANGE_REQUIRED`. |
| Password change | Needs the current password; revokes all *other* sessions. |
| CSRF | (1) `sameSite=lax`; (2) CORS = `CLIENT_URL` only + JSON-only API; (3) `verifyOrigin` rejects non-GET requests whose Origin/Referer is another site (`403 CSRF_REJECTED`). Requests without Origin (curl, tests) are allowed — they carry no browser cookies. |
| Sockets | The handshake reads `tl_access`; staff join `perm:<permission>` and `user:<id>` rooms; anonymous clients (TV) only get public signals. |
| Idle timeout | Frontend: warning at 13 min, sign-out at 15 min. |

## 7. Roles & permissions (RBAC)

**Code checks permissions, never role names.** The only place roles are mapped to permissions is
`src/config/permissions.ts` (`PERMISSIONS`, `ROLE_PERMISSIONS`, `roleHasPermission`).

```ts
router.post("/", authenticate(), requirePermission("patient:create"), validateRequest(schema), controller.create);
router.use(authenticate(), requirePermission("user:manage")); // whole router
```

- A denial answers `403 FORBIDDEN` **and** writes a `PERMISSION_DENIED` audit entry.
- The frontend has a **generated copy** (`frontend/src/lib/permissions.ts`). After changing the map run
  `npm run permissions:export`; `tests/unit/permissions.test.ts` fails if the copy is stale.
- **Object-level rules** (e.g. "a doctor sees only their own patients") are checked in services after
  loading the record, with `assertCanAccess(req, allowed, { entityType, entityId })` from
  `middlewares/authorize.ts` (writes an audit entry on denial). Prefer filtering list queries by owner;
  answer 404 when even the record's existence is private. `User.doctorProfile` links a doctor account to its
  Doctor record (Phase 3).
- **Adding a permission:** add to `PERMISSIONS` (with a human description) → assign in `ROLE_PERMISSIONS` →
  `npm run permissions:export` → use in the route → set `permission` on the menu item in the frontend
  nav config → add a least-privilege test if relevant.

Least privilege: reception = basic patient info, booking, queue, payments (no diagnosis/prescriptions) ·
doctor = full EMR of own patients, prescriptions, lab orders (no billing) · nurse = vitals + waiting list ·
lab = results/uploads (verification separate) · pharmacist = medication part only, dispensing, stock ·
accounts = money only · management = read-only analytics · super_admin = users, settings, audit,
automation (no clinical data) · patient = own records only.

## 8. Audit log

- Write: `await recordAudit({ req, action, entityType, entityId, before, after, meta })` from
  `modules/audit/audit.service.ts`. It takes actor/IP/user agent from `req`, removes any key matching
  `password|token|hash|secret|otp`, and **never throws** (failures go to the error log).
- Actions: `LOGIN`, `LOGIN_FAILED`, `ACCOUNT_LOCKED`, `LOGOUT`, `LOGOUT_ALL`, `TOKEN_REUSE_DETECTED`,
  `CREATE`, `UPDATE`, `DELETE`, `VIEW`, `ROLE_CHANGE`, `ACTIVATE`, `DEACTIVATE`, `PASSWORD_CHANGE`,
  `PASSWORD_RESET`, `PERMISSION_DENIED`. Add new actions to `AUDIT_ACTIONS` (and to the frontend
  `features/audit/audit-meta.ts` labels).
- **Append-only:** the model throws on any update/delete; there are no edit endpoints. In production the DB
  user should also have no update/delete rights on `auditlogs`.
- Audit every create/update/delete of clinical, financial and account data, with `before`/`after` snapshots
  of the meaningful fields.

## 10. Testo Life Assistant (patient chat) — how it works

```
Patient message
  → [1] Emergency guardrail in code (Bangla/English/Banglish keywords) — match → fixed safe reply
        ("come to Emergency / call 999") + staff alert; the AI is not called at all
  → [2] Gemini with a system prompt: no diagnosis, no medicines, confirm before booking,
        reply in the patient's language, call itself "Testo Life Assistant", never claim to be human
  → [3] Tools with real data: list_departments, search_doctors, get_available_slots,
        book_appointment, find_my_appointments, handoff_to_human
  → reply (+ booked appointments; hand-offs appear in reception's Assistant Alerts)
```
- Facts (doctors, fees, slots) only come from tools; double booking is blocked by a unique index.
- Limits: 20 messages/min per IP, last 20 messages as history, max 6 tool rounds, retry + fallback models.
- The same `handleChatMessage()` service can serve a WhatsApp webhook later (Phase 12).

## 11. Testing

- `npm test` → Jest. `tests/setup/global-setup.ts` starts **one in-memory MongoDB**; `test-env.ts` gives each
  test file its own database and safe env values (bcrypt cost 4, reuse grace 0, high rate limits).
  The first run downloads a MongoDB binary once.
- `tests/helpers.ts`: `useTestDatabase()`, `createUser({ role, email, … })`, `signIn(email)` (a Supertest agent
  that keeps cookies like a browser), `cookieValue()`.

- Every new endpoint needs: happy path, validation error, 401 without session, 403 for a role without the
  permission (and that it is audited), plus business-rule tests.
